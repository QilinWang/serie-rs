## Data comparison: six existing cases

Three builds were compared, with the same inputs and existing settings:

1. Rust 1.97.1 with the previous lock.
2. Rust 1.99.1 with the previous lock.
3. Rust 1.99.1 with the updated lock.

The CLI generated Lorenz without a shock, Lorenz with the existing parameter
shock, and OU without a shock. Each used its existing trajectory seed `42`,
noise base `1000`, eight Gaussian draws and sigma `0.1`. Existing bank tests
also generated OU data with Student-t(3), Laplace and contaminated noise,
using their existing two trajectory draws and three noise draws. These are
reproducibility checks using existing fixtures, not newly approved scientific
protocols.

Across the three builds, all **15 saved f32 tensors** in the six cases were
byte-identical: 2,785,025 scalar values per build, with zero changed bit
patterns. This includes `clean [trajectory_draw, time, channel]`,
`noise [noise_draw, time, channel]`, and, where exported,
`noisy_sigma_0.1 [time, channel]`. Their parsed safetensors metadata matched;
the three CLI manifest contents also matched. Individual shapes and tensor
hashes are in [the comparison receipt](upgrade-array-comparison-2026-11-04.json).
The existing Lorenz figure regenerated with the updated data has the same SVG
geometry and key tensor hashes. Full-file safetensors hashes can differ due to
header ordering and were not used as evidence of tensor inequality.

## Existing f64 fixtures

A separately runnable [comparison example](../serie-rs/examples/upgrade_f64_parity.rs)
collects f64 bit patterns using inputs from existing tests. The same example
was run against all three builds and once from the unpacked updated crate. All
four full JSON outputs were byte-identical; one retained
[reference result](evidence/upgrade-f64-reference-2026-11-04.jsonl) has SHA-256
`758bcef654bad419bd1341b82201c676796156a623222d1e7e98d95b8882e467`.

- The existing linear canary covers all 33 action sequences. Its action Jacobian
  has layout `[future_timestep, state_coordinate, action_timestep,
action_coordinate] = [8, 2, 8, 2]`; means, covariance, local and accumulated
  Jacobians, action coverage SVD, and A/B canary reports are included.
- The existing controlled Lorenz case has 3 future timesteps, 3 state
  coordinates and 1 action coordinate; its action Jacobian is `[3, 3, 3, 1]`.
- The existing pendulum case has 4 future timesteps, 2 state coordinates and 1
  action coordinate; its action Jacobian is `[4, 2, 4, 1]`.

These are exactly the existing fixture inputs, not new scientific settings.
The JSON records f64 values as integer `to_bits()` values. nalgebra matrices
record their dimensions and **column-major** iteration; `Array4` values use
logical iteration order with their full shape. Python's integer JSON parser was
used for comparison so the 64-bit patterns were not rounded through a
JavaScript number. This is strong evidence for these fixtures, not every
nalgebra function, input, RNG distribution, hardware platform, or training run.

## API adaptation and verification

`sha2 0.11` no longer formats its digest result using the prior `LowerHex`
implementation. `dgp_bank.rs` now formats the same digest bytes as two-digit
lowercase hexadecimal; the SHA-256 input and first-16-character fingerprint
remain the same. The existing known-data checks passed on available local
assets, including the full-array digest and HuGaDB 40-value prefix digest. A
new test checks leading zeros and byte order in hexadecimal rendering. ETTm1
and ETTm2 could not be checked because their assets were missing.

The updated `.crate` contained 27 files and had SHA-256
`236e349a466765392a95205a3caa4b83fd3e929b8b04f60588210f8d73f126d1`.
Cargo verified the package; tests then ran from a separate extracted directory
with `cargo +1.99.1` explicitly selected: **121/121 default** and **213/213
all-feature** library tests, subject to the two skipped asset branches above.
The extracted CLI listed nine systems and the extracted f64 example reproduced
the same reference result. Build and test used one Cargo job and one test,
Rayon, OpenMP and BLAS thread. No model was trained, scientific setting
changed, or artifact published to crates.io.
